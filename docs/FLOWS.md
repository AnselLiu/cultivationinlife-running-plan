# 耕跑團 App 操作流程

這份文件記錄 App 每一個主要操作的步驟，以及流程上的設計原則。改功能時請同步更新；有自動測試的流程，在最後一欄標出測試檔。

自動測試涵蓋：
- **API 測試** 148 組（`npm run test:ci`，連同單元測試、執行額度與其他伺服器測試共 377 組）：權限、資安、所有寫入流程。
- **瀏覽器端到端測試** 195 組（`npm run test:e2e`，iPhone 尺寸），範圍是：
  - 團員：課表、GPS 跑步（模擬定位）、拍照、行事曆、地圖、我的各頁、通行金鑰（模擬 Face ID）、會籍卡、分享 App、通知、挑戰、使用說明、推薦人、成績與挑戰（登錄成績與截圖、PB 卡、目標挑戰、取消的挑戰不給操作、見證制體重、恭喜榜與 LINE 分享、隱私開關、英文條件句）、先 Google 再通行金鑰（綁定 Google 的確認卡與取消、新手機新增通行金鑰）。
  - 幹部：協會強制兩步驟時用 Google 登入後的驗證面板、定期揪跑、邀請制、代為團體報名、餐敘（春酒、慶功宴）報到抽獎、索票與發票、發布通知或異動（含請已報名的人重新確認）、分團公告、收款、刪除。
  - 管理後台：審核、會籍卡驗證、指派身分、重設通行金鑰並登出、恢復連結（複製、用 LINE 傳給本人，本人沒登入打開連結用 Google 接回原本的帳號）、設定、備份、稽核、推薦族譜、成績與挑戰（功能開關與權限、成績審核與截圖檢視、挑戰編輯與發布、團服結算與發放、CSV、見證〔同一個見證碼重讀不再送〕、監事唯讀、稽核標籤）。
  - 主要頁面的無障礙（axe，淺色與深色）與版面不超出手機畫面，含成績與挑戰的團員頁與後台頁。
- **Lighthouse**（`npm run test:lh`）：5 個頁面的效能、無障礙、最佳做法。

GitHub 每次推送都會跑這三種，全部通過才部署。

- e2e 是 `tests/e2e/`（Playwright，iPhone 尺寸的真實瀏覽器）。
- api 是 `tests/api.test.mjs`。

## 共通原則

| 原則 | 做法 |
| --- | --- |
| 每一頁都能回去 | 分頁以外的頁面，左上角都有「‹ 上一頁名稱」。<br>在 App 裡有上一頁就退回上一頁（保留捲動位置與篩選）。<br>從通知或分享連結直接打開的，就回到它的上一層。<br>加到主畫面後沒有瀏覽器的返回鍵，所以這個按鈕一定要有。 |
| 不會送出兩次 | 表單送出後，送出鍵會停用並轉圈，所有寫入完成才恢復。<br>沒有表單的按鈕（我要報名、確認收款）也一樣。 |
| 做完告訴你下一步 | 成功的提示要說「發生了什麼、接下來做什麼」，例如：<br>「報名完成，10/4（日）見」<br>「已建立，已通知 32 人」<br>「已建立邀請制活動，下一步：邀請人」 |
| 不會因為跳頁而重填 | 報名時被要求先填賽事報名資料，填完會帶回報名，剛才選的組別與商品都還在。<br>新增活動填到一半跑去地圖新增地點，回來會帶回草稿。 |
| 搜尋不用按鈕 | 名冊、會員查詢、指派身分、移交理事長、邀請、分團名冊、加入分團：打字停 0.3 秒或改下拉選單就查；注音選字中不查；比較慢回來的舊結果不會蓋掉新的。名冊仍然要有條件（打一個字或選一個篩選）。 |
| 地址跟郵局一樣 | 先選縣市、鄉鎮市區（帶出 3 碼郵遞區號），再填路名門牌；填好立刻送中華郵政核對，換成郵局的寫法並顯示 6 碼郵遞區號。縣市與鄉鎮市區清單來自郵局（`tools/zip3.py` 可重新產生）。 |
| 危險操作用選擇，不用「確定／取消」 | 刪除定期揪跑時，三個選項分開列：「只刪這一場／連同之後 N 場／取消」，不會把「取消」當成「只刪這場」。 |
| 錯誤講人話 | 斷線顯示「目前沒有網路，連上後再試一次」，伺服器錯誤顯示「伺服器忙碌，請稍後再試」。<br>頁面載入失敗有「重試」與「回首頁」。<br>沒接住的錯誤也會跳提示，不會默默失敗。 |
| 空畫面有出路 | 沒有入場券時，提供「看接下來的活動」。<br>沒有通知時，提供「開啟手機推播」。<br>找不到紀錄時，提供「回課表」。 |
| 不擋人 | 隱私權政策改版時，最上面先列「這次更新了什麼」，底部固定「同意並繼續」，不用滑到最後。 |

## 團員

| 流程 | 從哪裡進 | 步驟 | 結果與通知 | 測試 |
| --- | --- | --- | --- | --- |
| 第一次加入 | 朋友分享的連結或 QR | 從活動連結進來的先看到活動預覽（類型、標題、時間、地點、報名狀態）→ 登入頁 → 用 Google 登入（或通行金鑰、邀請碼）→ 隱私權政策同意 → 首頁最上面是「開始使用」卡：加到主畫面、開推播（iPhone 要先從主畫面打開）、確認距離與組別，每一步可略過、整張卡可以稍後 → 三步做完才問要不要看五個分頁的導覽（之後從「我的 → 使用說明」再打開） | 成為跑友；主團由管理員設定；從活動連結進來的登入後回到那個活動 | api |
| 從 LINE 打開活動連結 | LINE 群組裡的活動連結（`/e/活動代碼`） | LINE 的預覽卡顯示類型圖、標題、日期與開始結束時間（時間暫定時標「（暫定）」，沒填時間寫「時間待定」）、地點名稱、報名狀態 → 點開直接用 Safari／Chrome 打開（連結帶 `openExternalBrowser=1`，LINE 裡不能用 Google 登入）→ 沒登入先看到活動預覽與報名狀態，登入後回到活動頁；已登入直接到活動頁 | 預覽卡不含名字、人數、費用、地址；私密分團與邀請制沒帶邀請代碼的活動只有一般的網站預覽。舊的 `/#/e/` 連結照常可用 | api、e2e member |
| 隱私權政策改版 | 任何頁面 | 自動轉到政策頁 → 看「這次更新了什麼」→ 按底部「同意並繼續」 | 回到原本要去的頁面 | e2e member |
| 報名一般團練 | 首頁卡片、行事曆、通知 | 活動頁 → 可以先寫「給主辦的備註」（選填，例子每次打開換一個）→ 我要報名 → 報名卡片上方出現提示（主辦有寫「報名成功訊息」就顯示那段，不然是「報名完成，日期見」）；正取或候補可以按「分享到 LINE 群組」，帶「我報名了【標題】日期 時間・地點」與活動連結（`/e/活動代碼?openExternalBrowser=1`），群組由本人自己選 | 前一晚 20:00 提醒、集合前 1–2 小時提醒。<br>指定地點又遇壞天氣時，前一晚會提醒。<br>邀請制活動只有拿得到邀請連結的主辦有分享按鈕；問卷與待審核沒有 | e2e member、api |
| 取消報名 | 活動頁 | 取消報名 → 確認（已繳費會提醒退費由幹部處理；截止後取消先提醒聯絡主辦）。活動開始後不能自己取消 | 有候補時第一位自動遞補並收到通知；已繳費或截止後取消會通知主辦。活動異動後在確認卡選「取消報名」記成「異動後取消」，不另外通知主辦（已繳費的照樣通知退費）。主辦的統計頁記下取消時間與方式；之後再報名排到最後，但保留第一次報名的時間 | e2e member、api |
| 報名需要審核的活動 | 活動頁（報名期間會寫「需主辦審核」） | 送出申請 → 活動頁顯示「審核中」→ 可以撤回申請 | 核准：收到「審核通過」（正取附繳費資訊，或候補第幾位）。婉拒：收到「未通過審核」，原因只在通知中心與活動頁。主辦沒處理的申請在活動結束後失效 | api、e2e officer |
| 尚未開放與已截止 | 活動頁、首頁卡片 | 還沒開放：顯示開放時間與倒數，時間到自動重新讀取。已截止：顯示「報名已截止」。活動卡片在時間地點那一行標示報名中、即將開放（開放時間）、額滿可候補、報名已截止、已結束、已取消、外部登記（App 裡不開放、用外部連結登記的；索票活動標開放索票、索票已截止），自己已報名的只標已結束與已取消，過去的團練不再標已結束 | 報名期間由伺服器用台北時間判斷，手機時鐘不準也一樣 | api、e2e member |
| 報名成功通知 | 活動有開「通知報名者」 | 報名成功、排入候補、送出申請、確認收款、退費 | 推播給本人；同一個活動的推播會取代裝置上的舊通知 | api |
| 報名帶攜伴 | 活動頁（主辦有開「可攜伴人數」，任何類型都可以，問卷除外） | 選攜伴人數 → 每位可以填姓名（選填，只有主辦看得到）→ 報名；修改報名會帶回人數與姓名 | 公開名單、貼 LINE 的名單只顯示「＋2」；主辦在統計頁與 CSV 看得到姓名；攜伴每位跟報名費同價。活動勾了「攜伴也佔名額」時，名額算本人加攜伴，剩下的位子不夠這一組就排候補（人數選單標「名額不夠，會排候補」、按鈕改成「排候補」，提示說明人數少的可能先遞補）；本人＋攜伴比整個名額多直接擋下；已經是正取再加攜伴，位子不夠會擋下（同時有人報名也一樣，寫入那一句再確認）。索票的張數用同一套名額算法 | api、e2e officer |
| 索票（觀賽票、公關票、電影票） | 首頁卡片、通知（活動類型「索票」） | 活動頁「要幾張？」選 1–N 張（N＝主辦定的每人上限）→ 有組別就選組別 → 我要索票；改張數、取消跟一般報名一樣 | 有開「通知報名者」時，正取收到「索票成功」（寫張數）。票發完就排候補，有人取消或減少張數依登記先後遞補，張數少的可能先遞補（剩下的票不夠的那一筆先留在候補）；一次要的比總張數還多直接擋下；主辦後來調低每人上限，已登記的人改備註保留原本的張數（只是不能再加），提示用伺服器存下的張數。「目前還剩 N 張」是還沒人登記的張數。首頁卡片、行事曆寫「已登記」，行事曆的數字也是張數。公開名單只寫張數 | api、e2e ev2 |
| 活動異動後確認 | 「改時間，請確認」這類通知、首頁卡片的「請確認」、活動頁的確認卡 | 活動頁上方的確認卡 → 「仍參加」，或「取消報名」→ 確認 | 仍參加：卡片消失，候補順位不變；取消報名：記成「異動後取消」，候補遞補。之後才報名的人不用確認；活動開始或取消後不再問（首頁與過去活動的卡片也不再標「請確認」） | api、e2e ev2 |
| 報名有組別、價格的活動 | 活動頁 | 選組別、加購商品 → 下方即時算出金額與優惠 → 我要報名 | 出現繳費卡：金額明細、收款帳戶（可複製）、繳費期限 | e2e member |
| 代為團體報名的賽事 | 活動頁 | 選組別 → 還沒填賽事報名資料時，被帶去填 → 填完自動回到報名，剛才的選擇都在 → 勾選同意提供 → 報名 | 主辦幹部才能下載（要通行金鑰驗證） | api |
| 回報繳費 | 活動頁的繳費卡 | 選方式（轉帳或現金）→ 填轉帳後五碼 → 我已繳費 | 幹部收到「有人回報繳費」，確認後狀態變「已完成繳費」 | e2e member |
| 團購領取 | 「到貨了」通知、我的 → 入場券與領取 | 出示領取 QR 給幹部掃 | 記錄已領取 | api |
| 記錄訓練 | 課表的「記錄」、首頁今天卡片、團練結束後的「跑完了嗎？」通知、跑步記錄完成 | 自動帶入當天課表 → 填距離與時間 → 儲存 → 「已記錄」頁 | 可以直接「拍照分享」（數字已帶入，不會重複存紀錄）或「回課表」 | e2e member |
| GPS 跑步（e2e features-member） | 跑步分頁 | 開始（不用等今天的課表讀完，讀到後再補上目標）→ 自動暫停（停 20 秒）→ 停超過 3 分鐘問「跑完了嗎？」→ 結束 → 存成訓練紀錄 | 路線只存在手機 | api |
| 拍照分享 | 跑步分頁 › 跑完之後 › 拍照分享（關掉 GPS 跑步時是「拍照」分頁）、記錄完成頁 | 選版型與尺寸 → 選照片或 AR 相機（可設定一打開就進 AR）→ 分享圖片或 6 秒短片 | 跑步中用 AR 拍，數字會即時跳動 | 手動 |
| 行事曆 | 首頁下方「行事曆」 | 點日期看當天的團練、賽事提醒、國定假日、自己的賽事 | 可以訂閱到手機行事曆（我的 → 行事曆訂閱，#/me/calendar） | api |
| 練跑地圖 | 地圖分頁、首頁天氣、活動場地 | 點地點 → 看說明、天氣與跑步建議、現場回報 → 回報現場（一小時一次）→ 導航 | 幹部按「在這裡開揪跑」；協會打開「團員揪團」時，團員按「在這裡發起揪團」；都不是就按「在 LINE 揪人」 | api |
| 畫路線 | 地圖右上「畫路線」 | 點地圖加點，或用 iPad 的 Apple Pencil 直接畫、打開「手繪」用手指畫 → 完成 → 命名存檔 | 可以下載 GPX、分享；幹部可以直接開揪跑，協會打開「團員揪團」時團員可以「用這條路線發起揪團」 | 手動 |
| 發起揪團（功能開關「團員揪團」，預設關閉） | 首頁「發起揪團」、分團頁「＋ 發起揪團」、行事曆某一天、地圖地點與路線（都只有沒有建立活動權限、而且有參加分團的團員看得到） | 精簡表單：標題、分團（自己參加的）、日期、集合與結束時間、地點（可選練跑地圖的地點與路線）、人數上限（空白＝不限）、報名截止、可攜伴人數與「攜伴也佔名額」、說明、報名成功訊息 → 建立 → 活動頁分享到 LINE 群組 | 建立後立即開放報名、不推播給任何人；活動標「揪團」、「發起：暱稱」；不能收費、問卷、審核、外連、定期、邀請制。每人同時最多 3 場還沒舉行的揪團、一小時最多發起 5 次。開團人可以編輯（分團不能換、已經過去的不能改日期；改日期、集合時間或地點時已報名的人收到通知）、刪除（已報名的人收到取消通知）、看統計與名單（正取與候補的姓名、暱稱、組別、備註與攜伴姓名；沒有收款與金額、加購、問卷回答、報名者參加的分團與跑團）、匯出 CSV、複製名單；點名、收款、通知或異動、整批匯入、審核與移出由幹部處理，幹部也可以編輯或刪除。開關之後關掉：不能再發起，已經開的開團人照常管理 | api、e2e features-member |
| 離線地圖 | 地點卡片「下載離線地圖」 | 存附近約 1.5 公里的地圖 | 沒網路也看得到 | 手動 |

## 跑者休息站的維護工具（`tools/rest-sync.mjs`）

Workers 免費方案每次執行只有 10 ms CPU、50 個子請求（D1 指令也算），大檔或多檔的來源在 Worker 裡解析不完。這些來源在 `src/rest.js` 的來源登錄表標 `local: true`，只由這個工具在電腦上同步；Worker 的排程與管理後台的「立即同步」都不跑它們。留在 Worker 的條件與實測數字寫在 `src/rest.js` 的登錄表上方。

| 步驟 | 指令 | 說明 |
| --- | --- | --- |
| 0. 第二批的金鑰（只要做一次） | 到環境部環境資料開放平臺 <https://data.moenv.gov.tw> 註冊會員、申請 API 金鑰；存進 macOS 鑰匙圈：`security add-generic-password -a "$USER" -s cil-moenv -w`（會提示輸入，不留在指令紀錄） | Cool map 涼適點（`cool`）與環境部全國公廁（`moenv`）都在環境部的 API 上，要這把金鑰；只有電腦上的工具用，**不用**設成 Worker 的 secret。沒有設定時工具跳過這兩個來源，管理後台裡它們維持關閉，其他來源照常 |
| 1. 試跑 | `node tools/rest-sync.mjs` | 預設只試跑：依序抓全部只由維護工具同步的來源（每個來源之間停 1 秒），用 Worker 同一套解析與清理，產生 SQL 檔（`.wrangler/rest-sync/`），印出每個來源的筆數、類型、丟掉的筆數、資料日期與 SQL 指令數，不寫資料庫。也可以只給來源代碼，例如 `node tools/rest-sync.mjs twd tprv` |
| 2. 寫進測試站 | `node tools/rest-sync.mjs --apply --env staging` | 重新抓一次、產生 SQL，再用 `npx wrangler d1 execute cil-run-staging --remote --env staging --file …` 寫入 |
| 3. 寫進正式站 | `node tools/rest-sync.mjs --apply --env production` | 同上，資料庫是 `cil-run`；`--apply` 沒有配 `--env staging` 或 `--env production` 會直接拒絕 |
| 第二批 | `MOENV_KEY="$(security find-generic-password -s cil-moenv -w)" node tools/rest-sync.mjs cool moenv`（試跑）；確認後同一行加 `--apply --env staging`，再 `--apply --env production` | 金鑰只從環境變數 `MOENV_KEY` 讀，只放進抓資料的網址，不印、不寫進 SQL 檔。全國資料只收**核准的跑點 1 公里內**的列：試跑用 migrations 的 171 個跑點，`--apply` 時先用 wrangler 讀那個資料庫裡核准的跑點。第一次同步成功時來源自動開啟（migration 0050 先關著）；之後在管理後台關掉就不再寫。跑點新增或搬移後再跑一次，新跑點附近才會有 |
| 4. 確認 | 系統設定 → 地圖資料 → 跑者休息站來源 | 看上次同步時間、筆數、資料日期；筆數掉太多時這裡會顯示錯誤 |

- **完整性條件寫在 SQL 裡**，不用先讀資料庫：來源在管理後台關閉就什麼都不寫；內容跟上次一樣只記同步時間；筆數掉到上次的 70% 以下就不寫、不停用，記下錯誤；其他情況只寫有變的列、停用清單不再出現的列（不刪除），更新 `rest_sources` 的上次同步、上次成功、筆數、資料日期，版本（rev）加 1。
- **幹部的資料不動**：同步不改 `hidden`、`fix`、`note`，也不碰幹部新增與整理清單的列（`manual`）。
- **資料檢查**：只收臺灣範圍內的座標；不收電話與管理人姓名（解析時就丟掉，寫入前再檢查一次欄位白名單與電話）；開放時間要 `public/hours.js` 的 `parseHours` 看得懂、而且沒有「不開放、休息、休館、清場」這類字樣（`parseHours` 會把它們誤判成開放）才放進標準欄位，否則只留原文。運動場館的補充說明大多寫的是學生游泳課、清場、午休這些不開放的時段，只有明確寫「開放時間」的才整理。
- **D1 限制**：每個 SQL 指令不超過 100 KB（大量列自動分批）；LIKE／GLOB 樣式不超過 50 bytes；超過就不產生 SQL。
- **金鑰**：第一批只連公開的開放資料網址，不用金鑰；第二批只讀環境變數 `MOENV_KEY`（不讀 `.dev.vars` 或其他金鑰），寫進 D1 用 wrangler 自己的登入（`npx wrangler login`）。
- **第二批的規則**：Cool map 的公有點（機關、圖書館、公園等）有飲水或廁所才收，標「免費公共」；超商、量販、銀行、郵局等店家與「合作涼爽點」（大學、醫院、宮廟等）標「待確認」，休息站卡寫「店家・待確認，建議先詢問」；公有與否先看來源的設施類型（公有涼爽點）與店家種類（某某政府），「東門市場」這類名稱不會被當成店家；臺北市的公有點不收（直飲臺、臺北公廁已有）；只有冷氣座位的點不收。營業時間是「24小時營業」的標「24 小時」；括號裡寫星期（「(二)~(六) 08:00–17:00」）或跨夜（「06:00–01:00」）的只存原文，不判斷開放中。環境部全國公廁一列是一間廁間（名稱帶「-女廁」「3F男廁」）：不收臺北市（臺北公廁已有；縣市欄是代碼 63000）、中油（中油無障礙公廁已有）與評等不合格的；同一地址 60 公尺內的廁間合併成一處，名稱去掉廁間與樓層字樣；加油站（看名稱）與商店、飯店、餐廳、影城的廁所標「店家（建議先詢問）」；管理單位與電話不存。地圖上跟其他來源同一處時（同類 60 公尺內同名、廁所 30 公尺內、店家廁所與有廁所的連鎖店 30 公尺內），官方免費的優先顯示，店家與待確認排在後面。
- **建議頻率**：直飲臺每週（暫停的直飲臺才會盡快消失），其他每月一次（第二批也是每月，或跑點有新增、搬移時）。`--mock` 用測試假資料檢查產生的 SQL（不連外），只能試跑或配 `--apply=local`（寫進本機開發用的資料庫），配測試站或正式站會直接拒絕。
- **實地檢查**：`node tools/rest-check.mjs` 抓真的來源，印出各來源筆數與 171 個跑點的覆蓋率（有金鑰時另外印「加入第二批之前 → 之後」）；`--mock` 用測試假資料檢查工具本身；任何來源失敗、或任何一類 500 m 內的點數比基準（寫在工具裡）少超過 10%，結束碼就是 1。

## 活動報名的規則

- **報名期間**：「報名開始」與「報名截止」都是台北時間，由伺服器判斷；截止那一分鐘仍可報名。沒填截止時，活動開始（集合時間，沒有集合時間就是當天 23:59）就截止；問卷是截止日當天 23:59。
- **狀態**：正取、候補、待審核、未通過、已取消。只有正取佔名額、佔庫存、有入場券、要繳費、收到活動提醒；待審核什麼都不佔，也不會出現在其他人看得到的名單。
- **遞補**：正取取消、被移出、移出受邀名單、調高名額、關閉審核、刪除帳號、取消「攜伴也佔名額」時，候補依報名先後遞補；永遠不會自動錄取待審核。活動開始後不再自動遞補。
- **攜伴與名額**：活動勾了「攜伴也佔名額」，名額算位子（本人＋攜伴）：報名時剩下的位子不夠這一組就排候補；遞補依報名先後，位子不夠的那一組先留在候補、換下一位（跟庫存不夠一樣），之後有更多空位再輪到它；寫入後再確認、剩餘名額、首頁卡片都用同一個算法。沒勾的活動（舊活動、API 建立的預設）每筆報名只算 1 位，跟以前一樣。**索票**是攜伴也佔名額的特例：伺服器一律設 count_guests＝1，張數＝1＋攜伴人數（每人上限＝可攜伴人數＋1，總張數上限＝名額），不收攜伴姓名。攜伴姓名是 JSON 陣列，最多「可攜伴人數」位、每位 20 字，只有主辦看得到，刪除帳號與資料保存年限跟報名一起處理。
- **異動重新確認**：活動記下最近一次「請已報名的人重新確認」的時間（reconfirm_at），報名記下本人按「仍參加」的時間（confirmed_at）；有效報名（正取、候補、待審核）的 MAX(confirmed_at, 報名時間) 早於 reconfirm_at 就是未確認，所以之後才報名、取消後重報的人自動算已確認，要求確認時不用逐人更新。按「仍參加」不改報名時間，候補順位不變；本人改報名內容不算確認。遞補不看確認狀態；沒回覆的不會自動取消。時間只記到秒，同一秒報名的算已確認。
- **同時報名**：報名時間只記到秒，同一秒依隨機代碼排序；寫入後再確認一次名額與庫存，超過的排候補。同一人同時送兩次只算一次。每人 10 分鐘最多 30 次報名或取消。
- **大量處理**：貼上名單代為報名、稽核完整性檢查在人數或筆數多時，伺服器每次處理到執行額度用完為止（免費方案一次執行 50 個子請求），App 自動接著送剩下的（最多 20 輪，還沒做完會提示再按一次）；每一輪都重新檢查權限、寫稽核，結果和一次處理相同。批次審核（核准、婉拒、移出、重新審核，一次最多 200 人）、關閉審核直接錄取、候補遞補、系列活動、獎品匯入、邀請名單、繳費標記、排桌、主團設定、國定假日匯入一律每一步一句寫完，句數跟人數無關。
- **取消紀錄**：每一筆報名記下最近一次取消的時間與方式（本人取消、主辦移出、主辦婉拒、主辦退回〔待審核的「移出（可再報名）」〕、取消邀請、申請逾期、異動後取消）和第一次報名的時間；取消後重新報名會清掉取消紀錄、排到最後，第一次報名的時間不變。統計頁、CSV（只有能審核的人）、本人的個資匯出都看得到。
- **時間一律台北時間**：報名名單、團體報名資料、抽獎紀錄的 CSV 與統計頁的「每天新增報名」都用台北時間。
- **姓名與代為報名**：名單上的姓名一律用帳號的姓名（伺服器決定），報名時送來的名字不收。貼上名單代為報名時，已經是正取、候補或待審核的人跳過、不改內容也不通知（以前會蓋掉本人的備註、問卷、加購與攜伴，待審核還會被直接核准），結果列出「已經在名單上」與「已經送出申請、等審核」（請到統計頁核准）的人。
- **備註只給主辦**：報名時的「給主辦的備註」只有這場的主辦與報到幹部看得到（統計頁名單、CSV）；公開名單、複製名單（貼 LINE）、餐敘的座位查詢都不顯示。本人在活動頁看得到自己寫的，修改報名內容時會帶回表單。
- **分享連結**：活動頁的「分享」「複製連結」「分享到 LINE」與 LINE 公告文字都用 `/e/活動代碼`（邀請制加上邀請代碼 `?t=`），貼到 LINE 的再加 `openExternalBrowser=1`。伺服器只幫連結預覽加上活動摘要（標題、日期與開始結束時間、地點名稱、報名狀態、類型圖），畫面跟首頁一樣，打開後轉成 `/#/e/活動代碼`。看不到的活動（私密分團、邀請制沒帶對代碼、不存在）回一般首頁，不透露活動是否存在。現場報到 QR 仍是 `/#/e/活動代碼/attend`，沒登入掃到的登入後回到報到頁。
- **團員揪團**（功能開關，預設關閉）：沒有建立活動權限的團員只能在自己參加的分團發起（不能全協會）、日期不能早於今天；類型固定「其他」（畫面標「揪團」）、公開、不審核、建立後立即開放，帶團欄位是開團人的暱稱；收費、組別、加購、優惠、收款、團體報名、問卷、外連、課表、餐點、成團門檻、地址、定期一律不收，建立時不推播。同時最多 3 場還沒舉行、沒取消的揪團（寫在同一句 INSERT 的條件裡，同時送出也不會超過），一小時最多發起 5 次。開團人（還是那個分團的團員）可以編輯基本欄位（改日期、集合時間或地點時伺服器通知已報名的人）、刪除、看統計與名單（只有姓名、暱稱、組別、備註、攜伴姓名）、匯出 CSV、看受邀名單；其他欄位沿用原值，分團不能換，已取消的不能改，已經過去的不能改日期。新增邀請、移出受邀、邀請連結只有幹部，而且只用在邀請制活動。收款、對帳、團體報名資料、點名、報到 QR、通知或異動、整批匯入、審核與移出、訂購單、座位與抽獎只有幹部。
- **伺服器產生的通知文字只有中文**，英文介面只翻譯畫面上的文字。

### 行為改變（這次上線）

1. 沒填截止時，改成活動開始時截止（以前會一直開放）。活動開始後還要讓人報名，請用幹部代為報名或現場報到 QR。
