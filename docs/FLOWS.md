# 耕跑團 App 操作流程

這份文件記錄 App 每一個主要操作的步驟，以及流程上的設計原則。改功能時請同步更新；有自動測試的流程，在最後一欄標出測試檔。

自動測試涵蓋：
- **API 測試** 27 組（`npm run test:ci`）：權限、資安、所有寫入流程。
- **瀏覽器端到端測試** 37 組（`npm run test:e2e`，iPhone 尺寸），範圍是：
  - 團員：課表、GPS 跑步（模擬定位）、拍照、行事曆、地圖、我的各頁、通行金鑰（模擬 Face ID）、會籍卡、分享 App、通知、挑戰、使用說明。
  - 幹部：定期揪跑、邀請制、代為團體報名、餐敘（春酒、慶功宴）報到抽獎、發布通知或異動、分團公告、收款、刪除。
  - 管理後台：審核、會籍卡驗證、指派身分、設定、備份、稽核。
  - 13 個頁面的無障礙（axe）與版面不超出手機畫面。
- **Lighthouse**（`npm run test:lh`）：5 個頁面的效能、無障礙、最佳做法。

GitHub 每次推送都會跑這三種，全部通過才部署。

- e2e 是 `tests/e2e/`（Playwright，iPhone 尺寸的真實瀏覽器）。
- api 是 `tests/api.test.mjs`。

## 共通原則

| 原則 | 做法 |
| --- | --- |
| 每一頁都能回去 | 分頁以外的頁面，左上角都有「‹ 上一頁名稱」。<br>在 App 裡有上一頁就退回上一頁（保留捲動位置與篩選）。<br>從通知或分享連結直接打開的，就回到它的上一層。<br>加到主畫面後沒有瀏覽器的返回鍵，所以這個按鈕一定要有。 |
| 不會送出兩次 | 表單送出後，送出鍵會停用並轉圈，所有寫入完成才恢復。<br>沒有表單的按鈕（我要報名、確認收款）也一樣。 |
| 做完告訴你下一步 | 成功的提示要說「發生了什麼、接下來做什麼」，例如：<br>「報名完成，10/4（日）見」<br>「已建立，已通知 32 人」<br>「已建立邀請制活動，下一步：邀請人」 |
| 不會因為跳頁而重填 | 報名時被要求先填賽事報名資料，填完會帶回報名，剛才選的組別與商品都還在。<br>新增活動填到一半跑去地圖新增地點，回來會帶回草稿。 |
| 搜尋不用按鈕 | 名冊、會員查詢、指派身分、移交理事長、邀請、分團名冊、加入分團：打字停 0.3 秒或改下拉選單就查；注音選字中不查；比較慢回來的舊結果不會蓋掉新的。名冊仍然要有條件（打一個字或選一個篩選）。 |
| 地址跟郵局一樣 | 先選縣市、鄉鎮市區（帶出 3 碼郵遞區號），再填路名門牌；填好立刻送中華郵政核對，換成郵局的寫法並顯示 6 碼郵遞區號。縣市與鄉鎮市區清單來自郵局（`tools/zip3.py` 可重新產生）。 |
| 危險操作用選擇，不用「確定／取消」 | 刪除定期揪跑時，三個選項分開列：「只刪這一場／連同之後 N 場／取消」，不會把「取消」當成「只刪這場」。 |
| 錯誤講人話 | 斷線顯示「目前沒有網路，連上後再試一次」，伺服器錯誤顯示「伺服器忙碌，請稍後再試」。<br>頁面載入失敗有「重試」與「回首頁」。<br>沒接住的錯誤也會跳提示，不會默默失敗。 |
| 空畫面有出路 | 沒有入場券時，提供「看接下來的活動」。<br>沒有通知時，提供「開啟手機推播」。<br>找不到紀錄時，提供「回課表」。 |
| 不擋人 | 隱私權政策改版時，最上面先列「這次更新了什麼」，底部固定「同意並繼續」，不用滑到最後。 |

## 團員

| 流程 | 從哪裡進 | 步驟 | 結果與通知 | 測試 |
| --- | --- | --- | --- | --- |
| 第一次加入 | 朋友分享的連結或 QR | 登入頁 → 用 Google 登入（或通行金鑰、邀請碼）→ 隱私權政策同意 → 首頁最上面是「開始使用」卡：加到主畫面、開推播（iPhone 要先從主畫面打開）、確認距離與組別，每一步可略過、整張卡可以稍後 → 三步做完才問要不要看五個分頁的導覽（之後從「我的 → 使用說明」再打開） | 成為跑友；主團由管理員設定 | api |
| 隱私權政策改版 | 任何頁面 | 自動轉到政策頁 → 看「這次更新了什麼」→ 按底部「同意並繼續」 | 回到原本要去的頁面 | e2e member |
| 報名一般團練 | 首頁卡片、行事曆、通知 | 活動頁 → 我要報名 → 提示「報名完成，日期見」 | 前一晚 20:00 提醒、集合前 1–2 小時提醒。<br>指定地點又遇壞天氣時，前一晚會提醒。 | e2e member |
| 取消報名 | 活動頁 | 取消報名 → 確認（已繳費會提醒退費由幹部處理；截止後取消先提醒聯絡主辦）。活動開始後不能自己取消 | 有候補時第一位自動遞補並收到通知；已繳費或截止後取消會通知主辦 | e2e member、api |
| 報名需要審核的活動 | 活動頁（報名期間會寫「需主辦審核」） | 送出申請 → 活動頁顯示「審核中」→ 可以撤回申請 | 核准：收到「審核通過」（正取附繳費資訊，或候補第幾位）。婉拒：收到「未通過審核」，原因只在通知中心與活動頁。主辦沒處理的申請在活動結束後失效 | api、e2e officer |
| 尚未開放與已截止 | 活動頁、首頁卡片 | 還沒開放：顯示開放時間與倒數，時間到自動重新讀取。已截止：顯示「報名已截止」 | 報名期間由伺服器用台北時間判斷，手機時鐘不準也一樣 | api、e2e member |
| 報名成功通知 | 活動有開「通知報名者」 | 報名成功、排入候補、送出申請、確認收款、退費 | 推播給本人；同一個活動的推播會取代裝置上的舊通知 | api |
| 報名有組別、價格的活動 | 活動頁 | 選組別、加購商品 → 下方即時算出金額與優惠 → 我要報名 | 出現繳費卡：金額明細、收款帳戶（可複製）、繳費期限 | e2e member |
| 代為團體報名的賽事 | 活動頁 | 選組別 → 還沒填賽事報名資料時，被帶去填 → 填完自動回到報名，剛才的選擇都在 → 勾選同意提供 → 報名 | 主辦幹部才能下載（要通行金鑰驗證） | api |
| 回報繳費 | 活動頁的繳費卡 | 選方式（轉帳或現金）→ 填轉帳後五碼 → 我已繳費 | 幹部收到「有人回報繳費」，確認後狀態變「已完成繳費」 | e2e member |
| 團購領取 | 「到貨了」通知、我的 → 入場券與領取 | 出示領取 QR 給幹部掃 | 記錄已領取 | api |
| 記錄訓練 | 課表的「記錄」、首頁今天卡片、團練結束後的「跑完了嗎？」通知、跑步記錄完成 | 自動帶入當天課表 → 填距離與時間 → 儲存 → 「已記錄」頁 | 可以直接「拍照分享」（數字已帶入，不會重複存紀錄）或「回課表」 | e2e member |
| GPS 跑步（e2e features-member） | 跑步分頁 | 開始 → 自動暫停（停 20 秒）→ 停超過 3 分鐘問「跑完了嗎？」→ 結束 → 存成訓練紀錄 | 路線只存在手機 | api |
| 拍照分享 | 跑步分頁 › 跑完之後 › 拍照分享（關掉 GPS 跑步時是「拍照」分頁）、記錄完成頁 | 選版型與尺寸 → 選照片或 AR 相機（可設定一打開就進 AR）→ 分享圖片或 6 秒短片 | 跑步中用 AR 拍，數字會即時跳動 | 手動 |
| 行事曆 | 首頁下方「行事曆」 | 點日期看當天的團練、賽事提醒、國定假日、自己的賽事 | 可以訂閱到手機行事曆（我的 → 行事曆訂閱，#/me/calendar） | api |
| 練跑地圖 | 地圖分頁、首頁天氣、活動場地 | 點地點 → 看說明、天氣與跑步建議、現場回報 → 回報現場（一小時一次）→ 導航 | 一般團員按「在 LINE 揪人」；幹部按「在這裡開揪跑」 | api |
| 畫路線 | 地圖右上「畫路線」 | 點地圖加點，或用 iPad 的 Apple Pencil 直接畫、打開「手繪」用手指畫 → 完成 → 命名存檔 | 可以下載 GPX、分享，幹部可以直接開揪跑 | 手動 |
| 離線地圖 | 地點卡片「下載離線地圖」 | 存附近約 1.5 公里的地圖 | 沒網路也看得到 | 手動 |
| 跑者休息站 | 地圖右上「底圖」選單 → 休息站（功能開關開啟時才有） | 地圖上出現飲水、廁所、淋浴置物、補給的灰色小圓點；上方類型 chip 可以多選、記在這支手機；縮放不到 13 級只提示「放大地圖看休息站」、不抓資料；地點卡有「附近休息站」（每類最近 2 處，離線時用上次的資料），點了看開放時間、使用方式、導航與出處 | 伺服器只收到約 2 公里的格子代碼，不收位置；離我多遠在手機上算 | features-member、a11y、safearea |
| 每月里程挑戰 | 課表的工具、iPad／電腦側邊欄的「訓練」 | 看自己的里程、每週有沒有練、徽章、分團對抗、排行榜（要在隱私打開） | 每月 1 號 09:00 推播上個月總結 | api |
| 會籍卡 | 我的 → 協會 → 會籍卡（協會會員才有） | 出示 QR 給幹部掃 | 到期前 30 天、7 天、當天提醒續費 | api |
| 分享 App | 我的 → 分享耕跑團 App | QR Code 給朋友當面掃，或用 LINE、手機分享、複製連結 | 只分享網址，不帶邀請碼 | 手動 |
| 切換英文 | 我的 → 外觀與語言 → 語言（#/me/display，深淺色與「分頁列只顯示圖示」也在這裡）；登入頁下方 | 中文或 English | 團員自己寫的內容（標題、姓名、地點）不翻譯 | e2e member |

## 幹部（協會幹部、分團團長與幹部）

| 流程 | 從哪裡進 | 步驟 | 結果與通知 | 測試 |
| --- | --- | --- | --- | --- |
| 開團 | 首頁「新增活動」、分團頁、行事曆某一天、地圖地點、路線 | 填標題、日期、集合時間、地點（可選練跑地圖的地點與路線）→ 建立 | 提示「已建立，已通知 N 人」。邀請制活動提示下一步「邀請人」 | e2e officer |
| 定期揪跑 | 新增活動 → 重複 | 選每週幾 → 結束日期 → 可勾「遇到國定假日不開」 | 一次建立每一場（最多 60 場），每場各自報名 | api |
| 團購 | 新增活動，類型選團購 | 加商品（尺寸、庫存、每人上限）→ 收款資訊 → 成團門檻 | 統計頁看數量、成團進度 | api |
| 發布通知或異動 | 活動頁 → 管理 → 發布通知或異動 | 改時間（可連日期）、改地點（可附地址）、提醒或通知、取消活動 → 寫說明 → 選通知誰（已報名的人／整個分團或全協會／邀請制的受邀者）→ 送出 | 選的對象收到推播；用外部表單登記的慶功宴沒有人在 App 報名，選第二個；取消的活動頁顯示「這場已取消」 | e2e officer、API |
| 餐敘（春酒、慶功宴、尾牙） | 新增活動 → 類型「餐敘聚會」 | 填開始時間、店名、地址；可放外部登記表單（Google 表單）或用 App 報名、攜伴、餐點 | 活動頁顯示地址與「導航」（Apple 裝置開 Apple 地圖，其他開 Google 地圖）；行事曆訂閱帶地址 | API、Safari 逐頁檢查 |
| 收款 | 活動頁 → 統計 | 看應收、已收、待確認、還沒收 → 只看待確認的 → 確認收款；或匯入銀行明細 CSV → 預覽對上幾筆 → 確認標記已繳 | 金額即時更新 | e2e officer、api |
| 到貨與領取 | 統計 → 到貨與領取；活動頁「掃描領取」 | 通知到貨（寫領取地點時間）→ 現場掃描領取 QR | 每個人記錄已領取 | api |
| 團體報名資料下載 | 活動頁或統計頁 | 下載 → 通行金鑰驗證（Face ID、指紋）→ 存檔 | 寫入稽核紀錄 | api |
| 報名設定 | 新增或編輯活動 → 報名設定 | 開放報名、報名開始與截止（新增時依後台預設自動帶入，改日期會跟著算，手動改過就不動）、需要審核、通知報名者 | 下方即時說明報名期間；截止改到過去、名額低於正取人數會先確認 | e2e officer、api |
| 統計頁審核 | 首頁「報名待審核」、待辦通知、活動頁「待審核 N」、統計頁 | 篩選（全部、正取、候補、待審核、未通過、已取消）→ 核准、婉拒（選原因）、移出、重新審核 → 勾選多筆整批核准或婉拒，或「全部核准」 | 核准依報名先後排正取，名額不夠的排候補；移出已繳費的標記待退費，統計頁可改成已退費並結掉待辦；監事不能審核；每批寫一列稽核，婉拒與移出每人一列（不記原因） | api、e2e officer |
| 關閉審核 | 編輯活動 → 取消勾選「需要審核」 | 還有待審核時跳出確認 → 確定 | 依報名順序直接錄取（額滿排候補）並通知；寫入稽核 | api、e2e officer |
| 刪除活動 | 活動頁 → 管理 → 刪除 | 選擇面板：只刪這一場、連同之後 N 場（定期揪跑）或取消 | 報名的人收到取消通知 | e2e officer |
| 審核入團 | 管理後台總覽最上方、分團頁 | 核准或婉拒 | 申請人收到通知；第一個核准的分團成為主團 | api |
| 賽事提醒 | 行事曆 → 新增賽事提醒 | 日期、類型（賽事、報名開始或截止、其他）、連結 → 可勾同時推播 | 出現在大家的行事曆訂閱；報名截止前一天手機提醒 | api |
| 地點審核 | 地圖 → 待審核的地點 | 通過或不通過 | 提議的人收到通知 | api |
| 驗證會籍卡 | 管理後台 → 會員 → 掃描會籍卡 | 掃描或貼上 QR 內容 | 顯示有效或已到期，並寫入稽核 | api |
| 休息站新增與修正 | 練跑地圖 → 底圖選單「新增休息站」或地點卡「附近休息站」的「新增休息站」（選位置跟新增地點一樣點地圖）；休息站卡的「修正」「隱藏」「編輯」「刪除」 | 新增：名稱、類型與細項、位置（臺灣範圍內）、開放時間（看不懂只存原文）、使用方式、https 外連；官方資料只能修正（位置、名稱、時間、說明、使用方式）、補充說明或隱藏，不能刪；整理清單與自己新增的可以整筆修改或刪除 | 同步不會蓋掉修正與隱藏；寫入稽核（`rest.add`、`rest.fix`、`rest.hide`、`rest.delete`） | api |

## 理事長與行政人員

| 流程 | 從哪裡進 | 步驟 | 結果 | 測試 |
| --- | --- | --- | --- | --- |
| 指派身分 | 管理後台 → 權限 → 指派身分 | 搜尋跑友 → 變更 → 選身分與職稱 → 通行金鑰驗證（有通行金鑰或協會開啟兩步驟時） | 對方要重新登入；寫入稽核 | api |
| 移交理事長 | 管理後台 → 權限 → 移交理事長 | 搜尋新任理事長 → 選自己移交後的身分 → 輸入對方姓名確認 → 通行金鑰驗證（有通行金鑰或協會開啟兩步驟時） | 雙方重新登入；寫入稽核 | api |
| 活動報名預設 | 系統設定 → 活動與報名 → 活動報名預設 | 新活動預設需要審核、通知報名者；報名開始（建立後立即開放或活動前 N 天幾點）、報名截止（活動開始時、活動當天或活動前 N 天幾點）→ 看預覽 → 儲存 | 只影響之後新增的活動；寫入稽核 | api、e2e admin |
| 國定假日 | 系統設定 → 活動與報名 → 國定假日 | 按「匯入 2027 年」（新北市資料開放平台，通常前一年 6 月後公告） | 行事曆標出放假與補班 | 手動 |
| 備份 | 系統設定 → 安全與隱私 → 每日加密備份 | 每天 03:00 起自動備份，保留 35 天；資料多時分段，在接下來的整點（必要時跨日）做完才出現在清單上。也可以按「立即備份」：資料少時當場做完，資料多時回「會在接下來的整點分段做完」 | 還原用 `tools/restore-backup.mjs`（新格式是目錄＋分段，工具會列出下載指令或加 `--fetch` 自己下載）；遙測表、通知中心、同步來的鏡頭清單不在備份裡（公路局用 `tools/cams-sync.mjs` 重新匯入） | api、budget |
| 開啟速度與錯誤 | 管理後台 → 總覽 | 看 7、30、90 天的開啟速度與前端錯誤 | 不記錄是誰 | 手動 |
| 執行額度 | 管理後台 → 總覽 → 執行額度 | 看排程工作（完成、等下個整點補做、失敗幾次）、推播佇列待送幾則、最常碰到額度上限的功能 | 失敗 3 次的工作停止重試並寫稽核；紀錄保存 90 天，名稱不含 id | budget |

## 自動發生的事（排程，每小時整點檢查）

免費方案一次執行只有 50 個子請求、CPU 10 ms：每小時先用一句查詢看哪些工作有事要做，依優先順序跑，額度不夠的留到下個整點。下表的時間是「最早」的時間，錯過或延後的整點會在同一天後面補做；集合前提醒排在最前面，每日備份開自己的執行（一個整點做一段），同一個整點的其他工作通常延到下一個整點。

| 時間 | 內容 |
| --- | --- |
| 前一晚 20:00 起 | 明天活動的提醒（20:00 之後才建立的明天活動，下一個整點提醒）。<br>有指定地點的活動，集合時間預報「不建議跑步」、大雨或空氣不佳時，另外通知報名的人；預報「不建議」時也通知主辦幹部「要不要調整」。 |
| 集合前 1–2 小時 | 集合提醒（那個整點被延後時，下一個整點只要還沒集合就補送，到集合時間就過期） |
| 每小時 | 到了「報名開始」時間推播「開放報名」（建立時有勾通知、不是定期揪跑；最晚 59 分鐘）。<br>活動結束 15 分鐘後（沒有結束時間就是集合後 135 分鐘）或活動取消，還在待審核的申請失效並通知本人。 |
| 每小時 | 推播佇列：送出還沒送完的推播（發通知的那次請求會先送一段，之後的請求也會順便送幾台）。<br>刪除帳號、調高名額、核准時空出的正取名額，當下沒遞補完的由候補遞補（排在其他工作後面，一個整點最多 5 場；候補都因為庫存不夠排不進去的場次，狀態沒變就不再試）。 |
| 每天 20:00 起 | 還有待審核的活動，提醒主辦幹部處理（有新的申請時一小時最多推一次） |
| 團練結束後 15 分鐘 | 「跑完了嗎？」通知，點進去直接記錄當天訓練 |
| 每天 03:00 起 | 加密備份（資料多時分段，接下來的整點陸續做完）；資料清理（過期的工作階段、180 天前的通知、90 天前的速度與錯誤紀錄、現場回報、30 天前的休息站回報、過期的推播佇列）排在備份之後，通常 04:00 |
| 每天 01:00、02:00、06:00 | 跑者休息站資料同步（排程工作 rest，功能開關開啟時；每個整點只跑一個到期的來源，開始前要有整份額度，約 10 個子請求，不夠就留到下一個允許的整點）：只跑兩個小來源，河濱租借站每週、新北河濱廁所每月。資料沒變就不寫；筆數掉到上次 70% 以下就不更新；失敗或執行被終止隔天再試（管理後台「執行額度」顯示「沒有完成，隔天重試」）。其他來源（直飲臺、臺北公廁、河濱廁所、中油、運動場館、臺灣騎跡）排程不跑，由維護工具同步 |

## 跑者休息站的維護工具（`tools/rest-sync.mjs`）

Workers 免費方案每次執行只有 10 ms CPU、50 個子請求（D1 指令也算），大檔或多檔的來源在 Worker 裡解析不完。這些來源在 `src/rest.js` 的來源登錄表標 `local: true`，只由這個工具在電腦上同步；Worker 的排程與管理後台的「立即同步」都不跑它們。留在 Worker 的條件與實測數字寫在 `src/rest.js` 的登錄表上方。

| 步驟 | 指令 | 說明 |
| --- | --- | --- |
| 1. 試跑 | `node tools/rest-sync.mjs` | 預設只試跑：依序抓全部只由維護工具同步的來源（每個來源之間停 1 秒），用 Worker 同一套解析與清理，產生 SQL 檔（`.wrangler/rest-sync/`），印出每個來源的筆數、類型、丟掉的筆數、資料日期與 SQL 指令數，不寫資料庫。也可以只給來源代碼，例如 `node tools/rest-sync.mjs twd tprv` |
| 2. 寫進測試站 | `node tools/rest-sync.mjs --apply --env staging` | 重新抓一次、產生 SQL，再用 `npx wrangler d1 execute cil-run-staging --remote --env staging --file …` 寫入 |
| 3. 寫進正式站 | `node tools/rest-sync.mjs --apply --env production` | 同上，資料庫是 `cil-run`；`--apply` 沒有配 `--env staging` 或 `--env production` 會直接拒絕 |
| 4. 確認 | 系統設定 → 地圖資料 → 跑者休息站來源 | 看上次同步時間、筆數、資料日期；筆數掉太多時這裡會顯示錯誤 |

- **完整性條件寫在 SQL 裡**，不用先讀資料庫：來源在管理後台關閉就什麼都不寫；內容跟上次一樣只記同步時間；筆數掉到上次的 70% 以下就不寫、不停用，記下錯誤；其他情況只寫有變的列、停用清單不再出現的列（不刪除），更新 `rest_sources` 的上次同步、上次成功、筆數、資料日期，版本（rev）加 1。
- **幹部的資料不動**：同步不改 `hidden`、`fix`、`note`，也不碰幹部新增與整理清單的列（`manual`）。
- **資料檢查**：只收臺灣範圍內的座標；不收電話與管理人姓名（解析時就丟掉，寫入前再檢查一次欄位白名單與電話）；開放時間要 `public/hours.js` 的 `parseHours` 看得懂、而且沒有「不開放、休息、休館、清場」這類字樣（`parseHours` 會把它們誤判成開放）才放進標準欄位，否則只留原文。運動場館的補充說明大多寫的是學生游泳課、清場、午休這些不開放的時段，只有明確寫「開放時間」的才整理。
- **D1 限制**：每個 SQL 指令不超過 100 KB（大量列自動分批）；LIKE／GLOB 樣式不超過 50 bytes；超過就不產生 SQL。
- **不讀任何金鑰**：只連公開的開放資料網址；寫進 D1 用 wrangler 自己的登入（`npx wrangler login`）。
- **建議頻率**：直飲臺每週（暫停的直飲臺才會盡快消失），其他每月一次。`--mock` 用測試假資料檢查產生的 SQL（不連外），只能試跑或配 `--apply=local`（寫進本機開發用的資料庫），配測試站或正式站會直接拒絕。
- **實地檢查**：`node tools/rest-check.mjs` 抓真的來源，印出各來源筆數與 171 個跑點的覆蓋率；任何來源失敗、或任何一類 500 m 內的點數比基準（寫在工具裡）少超過 10%，結束碼就是 1。

## 活動報名的規則

- **報名期間**：「報名開始」與「報名截止」都是台北時間，由伺服器判斷；截止那一分鐘仍可報名。沒填截止時，活動開始（集合時間，沒有集合時間就是當天 23:59）就截止；問卷是截止日當天 23:59。
- **狀態**：正取、候補、待審核、未通過、已取消。只有正取佔名額、佔庫存、有入場券、要繳費、收到活動提醒；待審核什麼都不佔，也不會出現在其他人看得到的名單。
- **遞補**：正取取消、被移出、移出受邀名單、調高名額、關閉審核、刪除帳號時，候補依報名先後遞補；永遠不會自動錄取待審核。活動開始後不再自動遞補。
- **同時報名**：報名時間只記到秒，同一秒依隨機代碼排序；寫入後再確認一次名額與庫存，超過的排候補。同一人同時送兩次只算一次。每人 10 分鐘最多 30 次報名或取消。
- **大量處理**：貼上名單代為報名、稽核完整性檢查在人數或筆數多時，伺服器每次處理到執行額度用完為止（免費方案一次執行 50 個子請求），App 自動接著送剩下的（最多 20 輪，還沒做完會提示再按一次）；每一輪都重新檢查權限、寫稽核，結果和一次處理相同。批次審核（核准、婉拒、移出、重新審核，一次最多 200 人）、關閉審核直接錄取、候補遞補、系列活動、獎品匯入、邀請名單、繳費標記、排桌、主團設定、國定假日匯入一律每一步一句寫完，句數跟人數無關。
- **伺服器產生的通知文字只有中文**，英文介面只翻譯畫面上的文字。

### 行為改變（這次上線）

1. 沒填截止時，改成活動開始時截止（以前會一直開放）。活動開始後還要讓人報名，請用幹部代為報名或現場報到 QR。
2. 正取在活動開始後不能自己取消；取消後重報排到最後，也不再適用早鳥；候補修改報名內容不會插隊。
3. 截止時間以前晚了 8 小時才擋，現在照台北時間準時截止。
4. 新活動預設「通知報名者」開啟，舊活動維持關閉；可以在後台「活動報名預設」改。
