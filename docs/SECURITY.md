# 資訊安全設計說明

> 對照標準：ISO/IEC 27001:2022 附錄 A（控制措施參考自 ISO/IEC 27002:2022）
> 適用範圍：耕跑團 PWA（`public/`）、API（`src/worker.js`）、資料庫（Cloudflare D1 `cil-run`）

## 先說清楚範圍

ISO 27001 驗證的對象是**組織的資訊安全管理制度（ISMS）**，不是單一軟體。要取得驗證，協會需要風險評鑑、適用性聲明（SoA）、政策文件、內部稽核與管理審查。

這份文件說明的是**系統本身已經落實的技術控制**，可以作為協會日後建立 ISMS 時的技術佐證。下表最後一欄的「組織面待辦」，需要協會自己決定與執行。

## 控制措施對照

| **A.5.15** | 存取控制 | 兩層 RBAC，每支 API 都在伺服器端檢查。**協會層**：理事長、理事、監事、行政人員、教練、跑友，權限細分為 10 項（建立活動、發布課表、報到、抽獎、看名冊、會員管理、指派身分、座位圖設定、稽核查詢、系統設定）。**分團層**（耕跑團、耕跑青年、小耕跑、核心團、耕建築…）：團長、幹部、團員，權限只作用在自己分團的活動與名冊；分團名冊不含電話 | 後台「權限」「分團」對照表；他團幹部呼叫回 403 |
| **A.5.15** | 資料可見範圍 | 私密分團的活動、LINE 群組連結只有該團團員看得到（列表與單筆 API 都過濾，分享連結預覽也不顯示）；問卷回答只有活動所屬分團的幹部與協會幹部看得到統計；報名備註只有這場的主辦與報到幹部看得到（統計頁、CSV），公開名單、貼 LINE 的名單文字、餐敘座位查詢都不帶備註 | 非團員查私密活動回 404 |
| **A.5.15** | 邀請制活動 | 活動可設為邀請制：只有受邀名單上的人看得到（列表、單筆、報名、座位、獎項 API 都檢查），分享預覽要帶正確的邀請代碼；邀請連結可隨時關閉或重新產生（舊代碼立即失效），用連結加入有次數限制並寫稽核；移出名單會一併取消報名與入場券 | 非受邀者查詢回 404 |
| **A.5.18** | 存取權限 | 邀請碼**只能**取得跑友身分；所有協會特權身分只能由理事長在後台指派；分團團長只能由理事長指派或撤換，團長再指派分團幹部，團長不能調整自己；以上都寫入稽核紀錄；系統初始的第一位理事長用一次性設定碼，之後失效 | 團長自行升降回 400／403 |
| **A.8.2** | 特權存取權限 | 特權帳號的工作階段：閒置 8 小時、最長 7 天就失效（一般跑友為閒置 30 天、最長 180 天）；**身分一變更，舊的工作階段全部作廢**，必須用新身分重新登入 | 變更身分後，對方舊 cookie 呼叫 `/api/me` 回傳未登入 |
| **A.5.3** | 職責區隔 | 監事只能看名冊、會籍與稽核紀錄，不能修改任何資料；稽核紀錄由理事長與監事查看，執行操作的行政人員看不到。監事不能審核報名：除了審核 API，任何會把報名變成「核准」的路徑（幹部代為報名、主辦本人報名＝核准、關閉審核直接錄取）都在 `doSignup` 統一檢查，監事即使兼任分團團長或幹部，代為報名的待審核仍是待審核、本人報名也要等審核；監事也不能留訓練回饋 | 監事呼叫寫入 API 回 403；`api.test`「監事兼分團幹部」 |
| **A.8.5** | 安全鑑別 | Google 登入（OpenID Connect 授權碼流程）：`state` 防 CSRF、`nonce` 防重放；ID Token 用 Google 公開金鑰（JWKS）驗 RS256 簽章，並檢查發行者、對象（client_id）、期限與 nonce；範圍只要 `openid profile`，不取 Email，資料庫只存 Google 的 `sub` | 程式碼 `googleCallback()`、`verifyGoogleIdToken()` |
| **A.8.5／A.8.6** | 嘗試次數限制 | 跑者休息站（免費方案 D1 每天 500 萬列讀取）：一格的清單每位跑友 10 分鐘 150 次，詳細與地點附近合計 10 分鐘 60 次，三者再共用每位跑友每天 300 次（`rate_limits` 24 小時窗；用完後這個 isolate 10 分鐘內不再查 D1；被 10 分鐘上限擋下的請求不扣每天的次數，地圖一直重試的格子不會把一天的額度用光）。結構上也限住每次的成本：地點附近、詳情、一格的結果依「地點／id／格子＋資料版本」快取在 isolate 記憶體（workers.dev 上 Cache API 沒有作用）與 Cache API，命中時不讀休息站的表；索引改成（格子, 修正後緯度, 修正後經度），地點附近只查跟 1 公里範圍重疊的格子、只讀範圍內的列（本機實測：一格 64 處的測試資料，地點附近從周圍 9 格 606 列降到 131 列，詳情 25 列）。讀取列數的上限是結構上的、不靠資料多寡：休息站的查詢在 SQL 裡只放索引的「格子＋緯度範圍」，經度範圍與暫停的列讀出來後才濾掉，所以讀到的每一列都算進 LIMIT 800，一次最多約 820 列（每格 1,024 處的測試實測；以前經度條件在 SQL 裡，被濾掉的列照樣算讀取，一次約「3 × 每格列數＋18」，沒有上限）。一位跑友一天最多 300 × 820 ≈ 25 萬列；真實資料最密的一格 189 列時一次約 590 列。所有次數限制在超過上限後不再更新計數，被擋的請求不寫 D1（每天 10 萬列寫入）。訓練紀錄寫入（新增、修改、離線補傳、舊版課表教練資料搬移都是 `POST /api/logs`）：每位跑友每天 600 次、10 分鐘 300 次（被 10 分鐘上限擋下的不扣每天的次數），日期最早到協會這一季第 1 週往前 400 天（`logFloor`，舊版資料搬移也先排除更早的），備註最多 300 字（超過回 400，不再默默截掉），整個請求最多 8 KB；加上每天最多 5 筆（新增與「修改時改了日期」都檢查，同一個陳述式判斷），一個帳號一天最多寫約 3,600 列，總筆數也被「5 筆 × 可以記的天數」限住。被限制時離線暫存區保留沒送出的、舊版資料搬移停下並提示之後再按（已上傳的會認出是已存在）。邀請碼：每個 IP 10 分鐘 8 次；初始設定碼：15 分鐘 5 次；報到：每位工作人員每分鐘 90 次 | 連續猜碼，第 9 次起回 429 |

| **A.5.34** | 照片不出裝置 | 拍照分享的照片在瀏覽器以 canvas 合成，照片與 AR 相機畫面都不上傳 | `public/studio.js` |

| **A.5.34** | 當事人權利 | 本人可以下載自己的所有資料（JSON），也可以刪除帳號；刪除時報名、入場券、通知、推播訂閱一併刪除，中獎紀錄匿名化保留給協會對帳。刪除的每一句 SQL 集中在 `src/erase.js`，還原備份時也用同一份。還原會把資料帶回備份時間點，所以之後本人做的撤回都要重做：`tools/restore-backup.mjs --sql` 一定要帶 `--withdrawals`（從正式資料庫的稽核紀錄唯讀查出備份開始之後的刪除帳號 `privacy.delete`、刪除賽事報名資料 `privacy.race_profile_delete`、停止分享訓練 `privacy.share_logs`、退出排行榜 `privacy.show_rank`、通知分類 `notif.prefs`、取消推播 `push.unsubscribe`、移除通行金鑰 `passkey.remove`（記金鑰 id 前 64 字）、登出所有裝置 `session.revoke_all`、退出或被移出分團 `team.leave`／`team.remove`／`team.reject`、停用或重新產生行事曆訂閱 `calendar.off`／`calendar.on`、刪除自己的訓練紀錄 `log.delete`、路線 `route.delete`、分團公告 `team.post_delete`，以及身分變更 `role.change`／`role.handover`／`bootstrap.chair`／`team.role`；正式資料庫不在時用較新備份的 `audit_log`）或明確寫 `--no-withdrawals`。wrangler 輸出不是成功的結果（例如印出錯誤）時工具整份擋下，不會當成「沒有撤回」；工具印出讀到的筆數，跟另外的筆數查詢比對。匯入的 SQL 最後重做：刪除帳號、刪掉賽事報名資料與代報名同意、分享與排行榜最後一次是關閉就關（同一秒有開有關以關閉為準）、通知分類照最後一次設定、刪掉取消推播或登出所有裝置的人的推播訂閱（之後在「通知設定」重新連上）、刪掉移除的通行金鑰、刪掉退出或被移出分團的那一列（不然那個分團的幹部又看得到他分享的訓練）、清掉行事曆訂閱網址（舊網址可能外流過）、再刪一次刪掉的訓練紀錄、路線與公告、身分與分團身分照時間順序重設成最後一次（降級的人重新登入不會拿回原本的權限；稽核 detail 結尾記 `｜role=代碼`、`｜team=分團 id`，舊紀錄照中文名稱，看不懂的列出筆數請人工確認）；抓到的稽核紀錄原樣補回（`INSERT OR IGNORE`，簽章照原本的）。D1 Time Travel 的步驟見 [`RESTORE.md`](RESTORE.md) | 「我的 → 隱私與帳號」；`restore.test` |
| **A.5.34** | 訓練紀錄 | 預設只有本人看得到；本人打開分享後，教練與分團幹部照同意書的字面只看得到完成率、里程與平均強度：團員總表給區間的完成次數、里程與平均 RPE，單一團員給每一筆的日期、課表位置、完成狀況與距離，再加區間合計與平均 RPE。平均 RPE 只算整週（週一到週日），而且那一週至少 3 筆有填強度才計入：查詢區間縮到一天或兩個區間相減，都拿不到單次的 RPE（殘餘風險：教練每天盯著看，同一週從 3 筆變 4 筆時可以推回第 4 筆，跟「平均」本身的性質一樣，已接受）；每一筆的時間（配速）、心率、RPE、感覺與備註伺服器就不回傳（本人自己的紀錄、報表與匯出照舊完整）；教練回饋照常；開關變更寫稽核。「教練與分團幹部」照同意書的字面：只有有課表權限的教練（理事長、教練）與該團員所屬分團的團長、幹部；理事、行政人員、監事的協會層級名冊權限不算，看不到團員訓練、也不能留回饋（監事兼分團幹部時看得到自己帶的團員，但不能留回饋）。幹部週報的訓練完成率只算打開分享的人（完成、部分、跳過的次數與總里程，都是聚合），分享的人少於門檻（協會 5、分團 3）整塊不顯示；理事長（有課表權限）看協會版、團長看自己分團的，行政人員的週報伺服器就不回傳訓練區塊（同上：協會層級權限不算「教練與分團幹部」）；殘餘風險：人數剛過門檻時，增減一人可推回個人的完成次數，跟「平均」同性質，已接受 | `/api/logs/team`、`/api/logs/member/:id` 只回傳同意範圍內的欄位；`api.test`「團員訓練只給教練與分團幹部」「分享給教練的訓練只有同意範圍」（含一筆一天查詢拿不到 RPE） |

## 已知限制

- 稽核紀錄有 HMAC 與每日摘要鏈，可以「偵測」竄改，但無法「阻止」擁有 Cloudflare 帳號權限的人改資料庫或部署新程式；Cloudflare 帳號本身要開啟兩步驟驗證並限制成員。
- 頻率限制以 IP 雜湊為單位；共用同一個對外 IP 的場地（例如活動現場 Wi-Fi）可能一起被擋，必要時可調整門檻。
- 幹部兩步驟驗證預設關閉，由理事長在「系統設定」開啟；開啟後沒有通行金鑰的幹部暫時只有一般跑友的功能。
- 分團團長與幹部沿用一般跑友的工作階段期限（閒置 30 天），因為他們只看得到自己分團不含電話的名冊；權限每次請求即時查詢，撤換後立即失效。若日後分團幹部可看到更多個資，應改用特權期限。
