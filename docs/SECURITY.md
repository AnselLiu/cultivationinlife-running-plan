# 資訊安全設計說明

> 對照標準：ISO/IEC 27001:2022 附錄 A（控制措施參考自 ISO/IEC 27002:2022）
> 適用範圍：耕跑團 PWA（`public/`）、API（`src/worker.js`）、資料庫（Cloudflare D1 `cil-run`）

## 先說清楚範圍

ISO 27001 驗證的對象是**組織的資訊安全管理制度（ISMS）**，不是單一軟體。要取得驗證，協會需要風險評鑑、適用性聲明（SoA）、政策文件、內部稽核與管理審查。

這份文件說明的是**系統本身已經落實的技術控制**，可以作為協會日後建立 ISMS 時的技術佐證。下表最後一欄的「組織面待辦」，需要協會自己決定與執行。

## 控制措施對照

| 附錄 A | 控制措施 | 系統怎麼做 | 驗證方式 |
|---|---|---|---|
| **A.5.15** | 存取控制 | 兩層 RBAC，每支 API 都在伺服器端檢查。**協會層**：理事長、理事、監事、行政人員、教練、跑友，權限細分為 10 項（建立活動、發布課表、報到、抽獎、看名冊、會員管理、指派身分、座位圖設定、稽核查詢、系統設定）。**分團層**（耕跑團、耕跑青年、小耕跑、核心團、耕建築…）：團長、幹部、團員，權限只作用在自己分團的活動與名冊；分團名冊不含電話 | 後台「權限」「分團」對照表；他團幹部呼叫回 403 |
| **A.5.15** | 資料可見範圍 | 私密分團的活動、LINE 群組連結只有該團團員看得到（列表與單筆 API 都過濾，分享連結預覽也不顯示）；問卷回答只有活動所屬分團的幹部與協會幹部看得到統計 | 非團員查私密活動回 404 |
| **A.5.15** | 邀請制活動 | 活動可設為邀請制：只有受邀名單上的人看得到（列表、單筆、報名、座位、獎項 API 都檢查），分享預覽要帶正確的邀請代碼；邀請連結可隨時關閉或重新產生（舊代碼立即失效），用連結加入有次數限制並寫稽核；移出名單會一併取消報名與入場券 | 非受邀者查詢回 404 |
| **A.5.18** | 存取權限 | 邀請碼**只能**取得跑友身分；所有協會特權身分只能由理事長在後台指派；分團團長只能由理事長指派或撤換，團長再指派分團幹部，團長不能調整自己；以上都寫入稽核紀錄；系統初始的第一位理事長用一次性設定碼，之後失效 | 團長自行升降回 400／403 |
| **A.8.2** | 特權存取權限 | 特權帳號的工作階段：閒置 8 小時、最長 7 天就失效（一般跑友為閒置 30 天、最長 180 天）；**身分一變更，舊的工作階段全部作廢**，必須用新身分重新登入 | 變更身分後，對方舊 cookie 呼叫 `/api/me` 回傳未登入 |
| **A.5.3** | 職責區隔 | 監事只能看名冊、會籍與稽核紀錄，不能修改任何資料；稽核紀錄由理事長與監事查看，執行操作的行政人員看不到 | 監事呼叫寫入 API 回 403 |
| **A.8.5** | 安全鑑別 | LINE Login（OpenID Connect）：`state` 防 CSRF、`nonce` 防重放，ID Token 交給 LINE 驗證端點檢查簽章、發行者、對象與期限，再比對 `sub` 與個人檔案的 userId | 程式碼 `lineCallback()` |
| **A.8.5** | 嘗試次數限制 | 邀請碼：每個 IP 10 分鐘 8 次；初始設定碼：15 分鐘 5 次；報到：每位工作人員每分鐘 90 次 | 連續猜碼，第 9 次起回 429 |
| **A.8.15** | 日誌 | 18 種特權與安全事件寫入 `audit_log`（身分變更、會籍、報到、抽獎、領獎、活動與課表增刪、座位圖、帳號建立與刪除、個資匯出、登入失敗等），記錄操作者快照與時間；應用程式**沒有**修改或刪除稽核紀錄的功能 | 後台「稽核紀錄」 |
| **A.8.16** | 監控活動 | 登入失敗與初始設定被拒也會記錄，可從稽核紀錄看出異常嘗試 | 稽核紀錄的「邀請碼錯誤」「初始設定被拒」 |
| **A.8.24** | 第三方權杖保護 | Strava 的存取與更新權杖以 AES-GCM（256 位元金鑰 `TOKEN_KEY`，每次隨機 IV）加密後才存入資料庫；授權範圍只要 `activity:read`，不要求私人活動；解除連結或刪除帳號時向 Strava 撤銷授權並刪除權杖 | `src/strava.js` |
| **A.5.34** | 照片不出裝置 | 數據照在瀏覽器以 canvas 合成，照片與 AR 相機畫面都不上傳 | `public/studio.js` |
| **A.8.24** | 密碼學 | 全程 HTTPS（HSTS 一年）；工作階段權杖 192 位元隨機值，資料庫只存 SHA-256；IP 以加鹽 SHA-256 雜湊後只留 16 碼；推播用 RFC 8291 加密 | `startSession()`、`ipHash()` |
| **A.8.26／A.8.28** | 應用程式安全、安全程式設計 | 所有使用者輸入在伺服器端限制長度與格式；畫面輸出一律跳脫（`esc()`）；SQL 全部參數化；寫入類 API 只收同源 JSON（擋 CSRF）；cookie 用 `__Host-` 前綴、`HttpOnly`、`Secure`、`SameSite=Lax` | 程式碼審查 |
| **A.8.23** | 網站過濾、內容安全 | 嚴格 CSP：只允許本站的程式與連線，圖片只允許 LINE 圖床；禁止被嵌入框架（`X-Frame-Options: DENY`）；`nosniff`；`Permissions-Policy` 只開放相機（掃碼用） | `public/index.html`、`public/_headers` |
| **A.5.34** | 個資保護 | 最小蒐集：身分證字號、地址**不進系統**（入會仍走協會 Google 表單）；電話只有可管理會籍的身分看得到完整號碼，其他人看到遮罩；LINE 大頭貼只接受 LINE 圖床網址 | 名冊 API 的 `phone` 欄位 |
| **A.5.34** | 當事人權利 | 本人可以下載自己的所有資料（JSON），也可以刪除帳號；刪除時報名、入場券、通知、推播訂閱一併刪除，中獎紀錄匿名化保留給協會對帳 | 「我的 → 隱私與帳號」 |
| **A.5.34** | 訓練紀錄 | 預設只有本人看得到；本人打開分享後，教練與分團幹部只看得到完成次數、里程與平均強度，看不到備註；開關變更寫稽核 | `/api/logs/team` 不回傳備註 |
| **A.8.6** | 容量管理（查詢效能） | 所有清單都要帶條件並分頁：稽核紀錄必選時間區間（預設 7 天、最長一年）、一次 50 筆；名冊不下條件不回傳名單；訓練紀錄自己最長 120 天、教練最長 31 天；通知 30 則一頁；過去活動依月份查；對應索引見 `migrations/0012` | 不帶條件呼叫名冊回傳空清單 |
| **A.8.12** | 資料外洩防護 | 報名名單 CSV 匯出：只有該活動的幹部可下載、寫稽核、電話欄只給可管理會籍者；儲存格開頭是 `= + - @` 會加 `'` 防公式注入 | `export.csv` |
| **A.8.10** | 資訊刪除 | 刪除帳號是實際刪除（資料表 `ON DELETE CASCADE`），不是軟刪除 | `DELETE /api/me` |
| **A.8.9** | 組態管理 | 所有秘密（LINE 金鑰、推播私鑰、初始設定碼、雜湊鹽）都放 Cloudflare secrets，不進 git；`.dev.vars` 列在 `.gitignore` | `wrangler.jsonc` 註解 |
| **A.8.32** | 變更管理 | 資料庫結構變更一律用編號遷移檔（`migrations/`），可追溯、可重複套用 | `migrations/0001`–`0013` |

## 組織面待辦（系統做不到，需要協會決定）

- [ ] 指定資訊安全負責人，並寫下資訊安全政策（A.5.1、A.5.2）
- [ ] 每季由理事長或監事檢視一次幹部名單與權限，移除已卸任的人；各分團的團長與幹部一併檢視（A.5.18）
- [ ] 每月看一次稽核紀錄，留意大量「邀請碼錯誤」或非預期的身分變更（A.8.16）
- [ ] 定期更換邀請碼，尤其是 LINE 群組成員大幅變動之後（A.5.17）
- [ ] 決定資料保存期限（例如：已結束超過 3 年的活動報名資料要不要刪），寫進隱私權政策（A.5.33、A.5.34）
- [ ] 在網站放上隱私權政策與個資蒐集告知（個資法第 8 條）
- [ ] 備份與還原演練：Cloudflare D1 有時間點還原（Time Travel，30 天），但要實際演練過一次（A.8.13）
- [ ] 帳號共用：提醒幹部不要共用帳號，報到現場每位工作人員用自己的帳號（A.5.16）

## 已知限制

- 稽核紀錄存在同一個資料庫，擁有 Cloudflare 帳號權限的人仍可以直接改資料庫。若要防竄改，下一步可以把稽核紀錄另外送到不可修改的儲存（例如 R2 物件鎖定或外部日誌服務）。
- 頻率限制以 IP 雜湊為單位；共用同一個對外 IP 的場地（例如活動現場 Wi-Fi）可能一起被擋，必要時可調整門檻。
- 沒有多因素驗證（MFA）。LINE 帳號本身支援雙重驗證，建議幹部開啟。
- 分團團長與幹部沿用一般跑友的工作階段期限（閒置 30 天），因為他們只看得到自己分團不含電話的名冊；權限每次請求即時查詢，撤換後立即失效。若日後分團幹部可看到更多個資，應改用特權期限。
